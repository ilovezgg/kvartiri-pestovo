# WORKFLOW — ритуал работы с памятью

## Старт сессии (до всего остального)

1. Прочитать `TASKS.md` в корне рабочей папки проекта.
2. Прочитать `PROJECTS/<slug>.md` этого проекта (если его нет — `PROJECT_INDEX.md` и `claude-migration/projects/*.md`).
3. Проверить `TIMELINE.md` §«Напоминания по датам» — если дата подошла, напомнить первым делом, не дожидаясь вопроса.
4. Проверить `DECISIONS.md` на ❌ — отвергнутое не предлагать снова.

## Во время работы

- Отмечать пункты TASKS.md сразу по ходу; «проверить позже» — записывать с датой.
- Секреты не писать никуда (только имена переменных/файлов).
- Оригиналы `~/.claude/` и `claude-migration/` не изменять.

## Конец сессии / значимого результата

1. Обновить `TASKS.md` проекта: сделано / дальше / проверить.
2. Если появились новые факты/решения/баги — обновить `PROJECTS/<slug>.md`, при изменении общих правил — `GLOBAL_MEMORY.md` / `DECISIONS.md`.
3. Новые грабли → `ERRORS_AND_LESSONS.md`. События с датами → `TIMELINE.md`.
4. Проверить: нет ли противоречий со старыми сведениями; устаревшее помечать OUTDATED, не удалять историю.
5. Не писать в память мелочи, которые не помогут продолжить работу через недели.

## Механизм подхвата Kimi Work

Kimi Work читает `AGENTS.md` из рабочей папки (проверено: блок next dev подхватывается автоматически). В `AGENTS.md` rent-next добавлена ссылка на `AI_MEMORY/` — при работе в этом проекте память подхватывается. При работе в ДРУГОМ проекте сначала открыть `C:\Users\stepa\Desktop\Projects\rent-next\AI_MEMORY\` вручную (путь записан в PROJECT_INDEX и в его TASKS.md/CLAUDE.md при необходимости). Нативный механизм vault-memory в Kimi отключён (07.11) — файлная система памяти является основной.
